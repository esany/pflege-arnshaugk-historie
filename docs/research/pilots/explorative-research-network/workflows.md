# Rekursive Forschungsworkflows

## 1. Kein singulärer Hauptworkflow

Dieser Pilot geht davon aus, dass anspruchsvolle Regional-/Quellenforschung nicht zuverlässig als eine einzige lineare Sequenz beschrieben werden kann. Mehrere Bewegungen greifen ineinander und dürfen sich wiederholen.

Das Ziel ist daher **nicht**, eine neue starre Pipeline zu definieren, sondern wiederkehrende Forschungsbewegungen sichtbar und restartbar zu machen.

## 2. Zentrale Bewegungen

### Material → Frage

Ein neu gesehenes Objekt, eine Karte, ein Museumslabel, eine Baustellenbeobachtung oder eine unbekannte Publikation erzeugt eine neue Frage.

Beispielstruktur:

`neues Material → Identität/Provenienz klären → Beobachtung formulieren → mögliche Relevanzen öffnen → Research Module anlegen oder bestehendes Modul verknüpfen`

Wichtig: Relevanz ist zunächst Candidate, nicht Finding.

### Frage → Material

Eine Forschungsfrage erzeugt gezielte Suche nach Quellen, Literatur, Vergleichsfundstellen oder Nachbardisziplinen.

`Research Module → Kompetenzrouting → Quellen-/Literaturbedarf → Search Boundary → neue Inputs → Prüfung`

### Überblick → Detail

Ein Muster auf regionaler Ebene legt eine enge Detailprüfung nahe.

Beispiel: Eine Fundstellenkarte macht eine räumliche Konstellation sichtbar. Erst danach wird geprüft, ob einzelne Fundstellen chronologisch, funktional und quellenkritisch überhaupt vergleichbar sind.

### Detail → Überblick

Ein einzelner belastbarer Befund kann die Synthese des größeren Raums verändern.

Beispiel: Eine neue Datierung, ein Provenienzproblem oder eine methodische Neubewertung einer Fundstelle kann eine bisherige regionale Gruppierung relativieren.

### Analyse → Synthese

Mehrere geprüfte Einzelbefunde werden in eine vorläufige Gesamtdeutung integriert.

Synthese muss sichtbar halten:

- welche Findings sie trägt;
- welche nur als Hypothese eingehen;
- welche Gegenbefunde/Unresolved States bestehen;
- welche Scale-Shift-Annahmen gemacht werden.

### Synthese → Analyse

Eine entstehende Gesamtdeutung erzeugt diskriminierende Detailfragen.

`Synthese-Candidate → kritische Annahmen identifizieren → Teilfragen bilden → relevante Inputs/Kompetenzen bestimmen → Detailprüfung`

### Disziplin → Nachbardisziplin

Die führende Kompetenz kann sich während der Arbeit ändern.

Beispiel:

`archäologischer Befund → geologische Entstehungsfrage → geoarchäologische Schnittstelle → Rückwirkung auf archäologische Interpretation`

Der Übergang ist selbst ein nachvollziehbarer Research-Schritt, keine automatische „Multi-Agent“-Aktivierung.

## 3. Question Lifecycle als Forschungsbewegung

Forschungsfragen können sich verändern:

```text
open
  ↕
working
  ├─ split → mehrere Teilfragen
  ├─ fuse → gemeinsame Frage
  ├─ reframe → andere Problemformulierung
  ├─ defer → später weiter
  ├─ reject → ungeeignete/falsche Voraussetzung
  └─ answered → belastbarer Zwischenabschluss
           ↘ kann durch neue Evidenz erneut geöffnet/reframed werden
```

`answered` bedeutet nicht „für immer wahr“, sondern: die Frage ist innerhalb dokumentierter Scope-/Evidence-Grenzen derzeit beantwortet.

## 4. Scale Shift

Scale Shift ist eine explizite analytische Operation.

Mögliche Ebenen:

`Objekt ↔ Kontext/Fundstelle ↔ Site ↔ Teilraum ↔ Orlatal ↔ regionale Vergleichsräume ↔ überregionale Forschung`

Vor einem Scale Shift soll mindestens geprüft werden:

- Was bleibt dieselbe Untersuchungseinheit und was ändert sich?
- Ist die relevante Zeitspanne noch vergleichbar?
- Ist die Quellen-/Datengrundlage auf beiden Skalen äquivalent?
- Wird nur Kontext ergänzt oder eine Beziehung behauptet?
- Welche neue Kompetenz/Methode wird durch den Maßstabswechsel nötig?

## 5. Explorative Divergenz und konvergente Synthese

Der Pilot braucht beides:

### Divergenz
- alternative Problemformulierungen öffnen;
- überraschende Materialien aufnehmen;
- Nachbardisziplinen aktivieren;
- mehrere Hypothesen nebeneinander führen;
- neue Maßstäbe testen.

### Konvergenz
- Evidenzqualität prüfen;
- Redundanz/Abhängigkeit erkennen;
- Fragen präzisieren;
- Findings begrenzen;
- Synthesen mit expliziten Grenzen formulieren.

Leitregel:

> **Exploration muss divergieren dürfen; Synthese muss konvergieren können; keine Synthese darf die zugrunde liegende Mehrdeutigkeit vernichten.**

## 6. Was automatisierbar ist

Hohe Automatisierbarkeit:

- Referenzen/Provenienzmetadaten pflegen;
- Material und Fragen verknüpfen;
- offene/unresolved Zustände sichtbar halten;
- mögliche Kompetenzbedarfe vorschlagen;
- Views ableiten;
- Restart-/Handoff-Kontext erzeugen;
- Frageänderungen und deren Gründe tracebar machen.

Urteilsgebunden:

- ob zwei Dinge historisch wirklich zusammenhängen;
- ob ein Scale Shift legitim ist;
- ob Evidenz eine Hypothese trägt;
- welche Fachmethode für einen Claim ausreichend ist;
- ob eine Synthese wissenschaftlich angemessen ist.

## 7. Minimaler Workflow für neuen Materialeingang

Nicht als permanente Produktpipeline, sondern als Pilot-Heuristik:

```text
1. Material erkennen/persistieren
2. konkrete Instanz/Provenienz soweit möglich bestimmen
3. Beobachtung von Interpretation trennen
4. vorhandene Relationen/Fragen prüfen
5. neue Relevanz nur als Candidate verknüpfen
6. bei materialer Frage Kompetenz/Methodenbedarf routen
7. Analyse/Synthese je Bedarf durchführen
8. neue Fragen/Relationen/Unresolved States externalisieren
9. vor Handoff Restartability prüfen
```

Kein Schritt verlangt, dass beim Eingang bereits eine Forschungsfrage feststeht.
